# HousesUnder150K — Articles Policy

This is the standing content standard for every article published on housesunder150k.com/articles. It exists so content is repeatable, structured, and built for actual SEO value rather than filler. Every new article should meet this bar before publishing — not after.

---

## 1. Minimum Article Requirements

An article is not ready to publish until it has all of the following:

| Element | Requirement |
|---|---|
| **Word count** | 2,500 words minimum. Thin content (under ~800 words) rarely competes against the established sites already ranking for these keywords. |
| **Structure** | A clear intro, 4–7 H2 subheadings, and a closing/bottom-line section. Break up any section running longer than ~150 words with an H3 or list. |
| **Citations** | Minimum 2–3 authoritative sources (.gov, established financial/real-estate publications, primary data providers). Linked in the Sources section at the bottom of the article — not just named in passing. |
| **Author** | Attributed to a real staff persona (currently: Jordan Reyes, Staff Writer) with a bio box. Never publish under a generic "Team" byline going forward. |
| **Featured image** | Required. Hero only — no inline images needed for this content tier. |
| **Keywords** | 5–6 target phrases, but see Section 3 — they must appear in the actual prose, not just listed. |
| **Internal links** | At least 1 link to another article (once 3+ exist) and 1 link to a money page (`/states`, `/listings`, or `/deal-of-the-day`). |
| **FAQ section** | Required. 4–6 Q&A pairs, visible on the page, directly relevant to the article's specific topic. See Section 9. |
| **Category** | One of: Buying Guide, Market Insights, State Spotlight, Financing. |

---

## 2. Structural Template (every article follows this shape)

1. **Intro** (75–125 words) — state the real answer/hook immediately. Don't bury the lede.
2. **Body** — 4–7 H2 sections. Each section should be able to stand alone as a snippet-worthy answer to a sub-question.
3. **"What to Expect" or "Bottom Line" closer** — practical takeaway, not a recap.
4. **FAQ section** — 4–6 Q&A pairs, visible on the page, placed before Sources. Questions must be directly relevant to the specific article topic — not generic real-estate filler. See Section 9 for full requirements.
5. **Sources** — 2–3 linked citations (bottom of page, already built into the template).
6. **About the Author** — bio box (already built into the template, auto-populates from the Authors collection).

---

## 3. On the "Keywords" section — read this before assuming it does more than it does

The visible Keywords line on the template is **not a meaningful ranking signal**. The old meta-keywords tag has been ignored by Google since 2009, and a plain list of phrases on the page is only marginally better than that. Its real value is close to zero on its own.

**What actually matters:** the same 5–6 target phrases need to show up naturally in:
- The **title** and at least one **H2**
- The **first 100 words**
- The **excerpt** (used as the meta description)
- The **body prose itself**, phrased the way a person would actually write it — not stuffed

Treat the Keywords field as a planning tool for the writer, not a ranking mechanism. If a keyword only exists in that list and nowhere else on the page, it isn't doing anything.

---

## 4. Citations — how to do this right

- Every factual claim about prices, programs, or statistics needs a real source behind it. Don't state a number you can't point to.
- Prefer **primary sources**: HUD.gov, USDA rd.usda.gov, consumerfinance.gov, Census/Zillow/FHFA data directly, state housing agencies.
- Secondary sources (Motley Fool, Opendoor, The Close, Norada, etc.) are acceptable for market-trend framing, but primary sources should anchor anything load-bearing.
- Never fabricate a statistic or cite a source that hasn't actually been verified as current and accurate. If unsure, search before publishing — don't guess.

## 5. Technical SEO (handled by the template — verify per article)

- **Dynamic SEO title/description** — auto-populated from Name/Excerpt. Confirm the excerpt reads well as a meta description (under ~160 characters, compelling, not truncated mid-thought).
- **Article JSON-LD schema** — auto-generated by the site-wide client-side footer script on all `/articles/` pages. Reads `#article-title`, `meta[name="description"]`, `.lp-hero-img`, `#article-meta-right`, and `#author-name` from the already-rendered DOM. No manual schema authoring needed per article. Note: Webflow's server-side JSON-LD field-token approach was tested and confirmed to silently produce empty strings for all fields — the footer script is the only reliable approach for schema on this site.
- **FAQPage JSON-LD schema** — auto-generated by the site-wide client-side footer script. The script detects the FAQ section by its wrapper class and builds the `FAQPage` schema from the visible Q&A pairs on the page. No manual schema authoring needed per article — but the FAQ section must be present and use the correct markup for the script to find it. See Section 9.
- **Related Articles** — auto-populated via a CMS Collection List on the article template. Shows the 2 most recent articles, sorted by Published Date descending, excluding the current article. Fully automatic — no action needed per article. See Section 10.
- **Clean slug** — should read as a natural keyword phrase, not a truncated title fragment.
- **Alt text** — featured image alt text auto-populates from the article title; fine as-is.

---

## 6. What this does *not* fix

Being honest about the ceiling here: this policy makes each article as strong as it can reasonably be on-page. It does not overcome:
- **Domain age/authority.** This is a brand-new domain with no backlink profile. Competitive head terms ("cheapest states to buy a house") will not rank quickly regardless of on-page quality.
- **Content volume.** Two or five well-built articles won't move topical authority much. This is a long-tail, cumulative play — expect it to compound over dozens of articles, not the first few.

The realistic target for early articles is long-tail, lower-competition variants (e.g., "USDA loan homes under $150k" rather than "cheapest homes in America"), plus internal-linking value to the listings/state pages.

## 9. FAQ Section — Requirements and Schema

### Why a visible FAQ section is required

Google's quality guidelines prohibit `FAQPage` schema on content that isn't visibly represented on the page. A hidden JSON-LD block with Q&A the user can't see is a policy violation and can result in rich result suppression or a manual action against the site. The FAQ section must be real, visible, on-page content — not a backend-only schema injection.

The upside: a well-written visible FAQ section earns two SEO benefits simultaneously — `FAQPage` rich result eligibility (the accordion-expansion format in SERPs) and featured snippet eligibility for each individual Q&A pair.

### Content requirements

- **4–6 Q&A pairs per article.** Fewer than 4 is thin; more than 6 starts to feel padded.
- **Questions must be specific to the article topic.** "What is a closing cost?" is too generic for a closing-costs article. "How much do I need at closing on a $150K FHA loan?" is the right level of specificity.
- **Answers must be direct and self-contained.** Each answer should fully resolve the question in 2–4 sentences without requiring the reader to scroll elsewhere. This is what makes them featured-snippet-eligible.
- **No duplicate questions across articles.** Each article's FAQ should be unique to that article's angle.

### Placement

The FAQ section sits after the body and any "Bottom Line" closer, and before Sources. It is a distinct, labeled section with a visible heading (e.g., "Frequently Asked Questions").

### Schema automation

The site-wide client-side footer script detects the FAQ section by its CSS wrapper class and auto-generates `FAQPage` JSON-LD from the visible Q&A pairs at page load. This means:
- No manual schema authoring is needed per article.
- The script only fires if the FAQ section is present and uses the correct wrapper class — confirm this is applied when building the article in Webflow.
- Google's crawler executes JavaScript and will index the injected schema. Social crawlers (Facebook, Slack, iMessage) do not execute JS — the FAQ schema is invisible to them, which is acceptable since FAQPage schema has no social-sharing use case.

### Intake template addition

Add FAQ pairs to the article intake template (Section 7):

```
FAQ (4–6 pairs):
Q: [question]
A: [2–4 sentence direct answer]
```

## 10. Related Articles — How It Works

The Related Articles section on every article page is fully automatic. No action is required per article.

### How it works

A CMS Collection List on the article template pulls from the Articles collection, sorted by Published Date descending, limited to 2 items, with the current article excluded via a Name filter. Every time a new article is published, it automatically becomes one of the two most recent articles shown on every other article page.

### What this means in practice

- **No manual linking required.** Do not try to manually set related article links — the Collection List handles this automatically.
- **New articles self-insert.** Publishing article 4 automatically makes it appear in the Related Articles section on articles 2 and 3 (the two most recent before it).
- **The section is template-level.** Changes to the Related Articles design affect all articles simultaneously.

### Technical notes (for future sessions)

- Collection List source: Articles; Sort: Published Date descending; Limit: 2; Filter: Name ≠ Current Name
- Inner card: LinkBlock (`ap-related-item`) containing Paragraph (`ap-related-label`) bound to Category field and H3 (`ap-related-title`) bound to Name field
- Link binding: set via Webflow Designer → select LinkBlock inside Collection Item → Settings → Link → Connect → Articles → URL Path. This is the **only** approach that works. Setting `collectionPage` mode via API always renders as `#` on the live site.
- CSS classes: `ap-related-wrap`, `ap-related-heading`, `ap-related-list`, `ap-related-item`, `ap-related-label`, `ap-related-title`
- An `article-url` Link field exists on the Articles CMS from a failed workaround attempt — it is unused and can be deleted.
